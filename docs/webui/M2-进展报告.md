## 2. M2 交付内容

### 2.1 控制面（我们自己的库，与上游产品库物理分离）

`src/web/control/ControlDatabase.ts` —— 独立 SQLite（`/data/registry.sqlite`），表：
`users` / `sessions` / `tenants` / `quota_counters` / `audit_log`，WAL + 外键。

> 为什么独立：上游产品库结构受 `check-database-schema` 约束、不容增删表；
> 用户与会话是本移植自己的概念，必须有自己的库。

### 2.2 认证

`src/web/control/AuthService.ts`：
- 口令 **scrypt**（Node 内置，零新依赖）；`timingSafeEqual` 比对。
- 会话令牌 32 字节随机，**库中只存 SHA-256 哈希**。
- 账号不存在时也执行一次同构哈希，避免用响应时间枚举账号。

`src/web/http/authController.ts`：
- `/login` 页面、`/api/auth/{login,register,logout,me}`。
- 按 **IP + 邮箱**双维度限流（15 分钟 10 次），挡住最直接的暴力尝试。
- 写操作校验 `Origin`（挡朴素 CSRF）。
- 会话 Cookie：`HttpOnly; SameSite=Lax; Path=/`，`Secure` 由 `ELECKOI_SECURE_COOKIES=1` 控制。

### 2.3 租户注册表

`src/web/TenantRegistry.ts`：
- **懒加载**：首次访问才挂载 cordis Context 与数据目录。
- **引用计数**：同一用户多标签页共享一个租户实例；全部释放后才开始计时。
- **空闲回收**：默认 30 分钟无引用即 `dispose`，释放 SQLite 句柄与 DSH 子进程。
- **挂载去重**：并发请求只挂一次。
- **上限保护**：超过 `ELECKOI_MAX_LIVE_TENANTS` 时淘汰最久未用的**空闲**租户；全在用则拒绝新租户。

### 2.4 多租户路由（安全边界）

`server.ts` 的门禁顺序：

```
Web 桥脚本（公开，无秘密）
  → 认证路由（/login、/api/auth/*）
    → 解析会话 Cookie ⇒ userId ⇒ 查租户 ⇒ registry.acquire
      → 借出 { gateway, mediaStore }，请求结束必须 release
```

**租户身份只来自服务端会话 Cookie**；客户端传来的任何 id 都不参与解析。
未登录时：页面 302 → `/login`，`/api/*` 返回 401，媒体路由同样不放行。

### 2.5 登录页

上游渲染层 UI **零改动**，鉴权入口由我们自己的页面承担（不参与应用 UI）。
无外部资源（无 webfont/CDN/图片），视觉沿用应用自身暗色气质：
深海底色墨青 `#0e1a1f`，单一强调色海藻绿 `#7fb09a` 只用在主操作与聚焦态，
衬线字标 + 无衬线正文，细线边框面板，圆角 2px。

### 2.6 生产入口与栈

- `src/web/stack.ts`：运行时栈工厂。**生产入口与验收测试跑同一套接线**。
- `src/web/entry.ts`：只做读环境变量、装信号处理、会话过期清理。

## 3. 容器验证（真实运行，非模拟）

镜像 `eleckoi-web:dev`（854 MB），经 `docker/compose.yml` 启动：

```
容器状态：Up (healthy)   端口 127.0.0.1:8799→8790
启动日志：数据目录 /data　开放注册 是　租户空闲回收 30 分钟
```

| 验证项 | 结果 |
|---|---|
| 未登录 `GET /` | `302 → /login` |
| `GET /login` | `200`，`<title>电子爱 · ElecKoi</title>` |
| 未登录 `POST /api/rpc` | `401`「登录状态已失效」 |
| 注册 `demo@eleckoi.local` | `{"ok":true}` + 下发会话 Cookie |
| 带会话 `GET /` | `200`，已注入 Web 桥 |
| 带会话读写设置 | `zh-CN-container` 写入并读回 |
| 数据卷 | `/data/registry.sqlite` + `/data/tenants/`（属主 `eleckoi`，非 root） |
| **重启容器** | `healthy`；旧 Cookie 仍可读回 `zh-CN-container`；未登录仍被拦截 |

### 3.1 构建层缓存优化

原先 `COPY . .` 在 `pnpm install` 之前，导致**改一行源码就重装 886 个包**（约 3 分钟）。
已改为：先复制清单与 `packages/` 装依赖，再复制其余源码——改 `src/` 不再触发重装。

（`packages/` 必须在安装前就位，因为根 `postinstall` 会构建三个 workspace 包。）

## 5. 尚未做（M2 剩余与 M3）

**M2 未竟**：
- 配额尚未真正生效（`quota_counters` 表已建但未接入每租户并发 run 上限与媒体配额）。
- DSH 空闲会话回收：`DshRuntime.sessions` 目前只在 `settingsKey` 变化或 `close()` 时释放；
  长会话用户即使闲置也会占着一个 node 子进程（租户回收能覆盖大部分场景）。
- 登录限流是进程内的：多实例部署需换共享存储。

**M3（公网加固，未开始）**：
- **富内容卡片跨源隔离**（方案 A）：`RichMessageFrame.jsx` 目前是 `srcDoc` 同源 iframe，
  角色卡 JS 可 `parent.eleckoi.request()` 打穿全部 IPC。公网前必须做，且需要 `patches/` 补丁。
- 媒体改**签名 URL**（卡片帧跨源时不带 Cookie）。
- CSP 等安全响应头（注意 srcdoc 会继承父文档 CSP，需先验证不误伤卡片）。
- 反向代理 + TLS 部署路径、备份与升级演练、AGPL 源码入口。
