# ElecKoi WebUI 发行说明

> 这份文件是 **GitHub Release 的说明正文**，由 `.github/workflows/web-image.yml`
> 在打 tag 时通过 `gh release create --notes-file` 直接读取。
> 发新版本前先更新这里，再打 tag——Release 上显示的就是 tag 那一刻的内容。

## 从 0.1.2 升级？**改一下镜像 tag 就行**

本版没有数据库结构变化，也没有需要手动执行的迁移。把 `docker/.env` 里的
`ELECKOI_IMAGE` 改成 `0.1.3`，然后 `docker compose -f docker/compose.yml up -d`。

新增的卡片图片白名单是**可选**的：不配就与 0.1.2 行为完全一致。

## 从 0.1.1 或更早升级？**也不需要做任何事**

上游在 0.1.2 的修订版（提交 `8f61b29`「修复旧版 Agent 预设数据库升级」）里补上了数据迁移：
v1→v2 的升级迁移会顺带把预设内容键 `tool_policy` 归一化为 `tool_configuration`，
并清理废弃的 roleplay-plan 行。**首次启动即完成，桌面端与 Web 端都一样。**

> 背景：0.1.2 最初发布时漏了这一步——键名改了却没有迁移，老库升级后预设页面会报
> 「预设缺少工具配置。」本分支的 0.1.2 / 0.1.2.1 曾自带一个迁移工具应急，
> 上游修复后已按「不重复维护」的原则移除。

桌面端若停留在旧版且不想升级，可以手动执行（**先关闭应用**）：

```sql
-- 在 %APPDATA%\ElecKoi\eleckoi-common.sqlite3 上执行
UPDATE agent_preset_contents SET kind='tool_configuration' WHERE kind='tool_policy';
UPDATE agent_preset_version_contents SET kind='tool_configuration' WHERE kind='tool_policy';
```

## 这是什么

[ElecKoi](https://github.com/eleckoi/ElecKoi) 的 **Docker 多用户 WebUI 分支**。

上游是 Windows 桌面客户端（Electron）。本分支让同一套内核以 **Docker 服务**运行：
浏览器打开就能用，一个实例可以服务多个用户，手机竖屏也做了适配。

**上游源码零改动。** 我们的东西全部以「新增文件 + 2 个构建期补丁」的形式存在，
由 `scripts/check-upstream-diff.mjs` 强制保证，因此上游更新时可以一条线 rebase。

## 怎么用

### 方式一：拉现成镜像（最快）

```bash
docker pull ghcr.io/darling2077/eleckoi-web:0.1.3

cp docker/.env.example docker/.env
openssl rand -base64 32        # 生成主密钥，填进 ELECKOI_MASTER_KEY
$EDITOR docker/.env
# 在 .env 里设 ELECKOI_IMAGE=ghcr.io/darling2077/eleckoi-web:0.1.3
docker compose -f docker/compose.yml up -d
```

### 方式二：从源码构建

```bash
git clone -b webui https://github.com/darling2077/ElecKoi-web.git
cd ElecKoi-web
cp docker/.env.example docker/.env
openssl rand -base64 32        # 生成主密钥，填进 ELECKOI_MASTER_KEY
$EDITOR docker/.env
docker compose -f docker/compose.yml up -d --build
```

**首次构建约 20–40 分钟**（apt 依赖 + 886 个 pnpm 包 + Electron 相关下载），
这不是卡住，请勿中断。用方式一可完全跳过。

完成后打开 `http://127.0.0.1:8790/login`，**注册的第一个账号自动成为管理员**。

## 部署前必须知道的三条

- `ELECKOI_MASTER_KEY` **一旦设定永不更换**。它是唯一能解开用户已存 API Key 的东西，
  换掉后那些 Key 全部无法解密且不可恢复。
- **公网部署必须同时配** `ELECKOI_CARD_ORIGIN` 与 `ELECKOI_APP_ORIGINS`，
  且两者必须是**不同的源**。只配前者服务会启动失败。
- 反向代理后必须开 `ELECKOI_TRUST_PROXY=1`，否则所有用户共用一个代理 IP，
  累计十次登录失败会让**全站**被限流十五分钟。后端读超时需 ≥300 秒
  （`POST /api/rpc` 会同步等待整个 Agent 回合结束才返回）。

完整说明见仓库 [`docs/webui/`](https://github.com/darling2077/ElecKoi-web/tree/webui/docs/webui)，
交给 AI 助手部署可让它直接读根目录的 [`CLAUDE.md`](https://github.com/darling2077/ElecKoi-web/blob/webui/CLAUDE.md)。

## 本版包含

### 本版内容（0.1.3）

- **卡片可以加载你自己的图床图片**（新增可选配置 `ELECKOI_CARD_IMAGE_ORIGINS`）。
  角色卡常把立绘写成外部图床地址，而卡片帧的 CSP 默认 `img-src 'self' data: blob:`
  会**拦掉请求**（不是加载失败——白名单外的图，图床服务器收不到任何请求），
  卡片里呈现为一块黑。现在把图床的**源**填进这个变量即可放行，逗号分隔可填多个；
  只接受纯源，带路径/查询串/通配符会拒绝并给出明确报错。
  **只放宽 `img-src` / `media-src`**，`connect-src` 仍为 `none`、脚本策略不变
  （验收里有专门断言守着这一点）。
- **配套工具 `docker/rewrite-card-images.mjs`**：把卡片里已有的外链图片批量下载到
  自己的图床并改写引用——卡片能正常显示，导出给别人时也不会因原图床删图而失效。
  扫描角色卡散落图片引用的全部位置，用**魔数**判定是不是图片（不靠扩展名猜），
  按内容哈希命名去重，默认 dry-run、幂等、改前自动备份、网络失败自动重试。
  实测一份真实租户库：25 个外部 URL → 16 张图、9.1 MB 落盘、改写 3 条记录。
- **可选自带一个图床（Zipline）**：`docker compose --profile images up -d` 会额外起
  Zipline + Postgres，别人能注册（凭邀请码）、上传、翻自己的图、复制链接。
  **不启用就完全不受影响**——默认那条 `up -d` 解析出的服务仍只有 `eleckoi-web`。
  启用方式、邀请码与配额、Lucky 子域分流、API 令牌见下面的文档。
- **导入卡片时自动搬图，进度条走完才算导入成功**：配好图床后，在浏览器点「导入」，
  界面右下角会出现进度条（「正在把卡片图片搬到你的图床… 12/341」），图片下载、上传、
  卡里的引用改写全部完成后才提示成功。默认同步执行，因此卡一出现就是最终态，
  不存在"图还在换、人已经进去聊天"的中间态。搬运做在我们自己的网关层（不改上游前端），
  4 路并发，扫到的非图片与本机地址会先排除。
- **四种做法可选，代价写在明面上**：放行第三方图床（纯配置，但数据会发给对方）、
  内联 `data:` URI（工具 `--inline`，不用图床且导出即自带，代价是卡片数据膨胀——
  实测 8 张图内联后记录从 1.9 万字符涨到 474 万字符，故默认只内联 256KB 以下的图）、
  本地图床（纯自用，别人导出后打不开）、自建公网图床（推荐，导出后别人也能取到图）。
- **文档**：新增 [`docs/webui/卡片外链图片本地化.md`](https://github.com/darling2077/ElecKoi-web/blob/webui/docs/webui/%E5%8D%A1%E7%89%87%E5%A4%96%E9%93%BE%E5%9B%BE%E7%89%87%E6%9C%AC%E5%9C%B0%E5%8C%96.md)，
  开头就是方案对照表（怎么配 / 卡片能否显示 / 导出给别人 / 数据去了哪 / 适合谁），
  其后是"图能单独打开但卡片全黑"的排查顺序、图床搭建与安全边界；
  `docker/rewrite-card-images.mjs` 既能把图传进图床服务（`--upload-api`），
  也能落到本地目录（`--upload-dir`）。

> **安全提醒**：放行图床等于承认卡片能通过图片 URL 把数据发出去。放行**自己的**
> 图床，数据最多落在你自己的访问日志里；放行 postimg.cc 这类**公共**图床，
> 等于把聊天内容公开——不要在 `ELECKOI_CARD_IMAGE_ORIGINS` 里填第三方公共图床。

### 上一个版本（0.1.2）

- **同步上游 v0.1.2**：`d5d02ec`「完善桌面 Agent 运行时与内容管理能力」（161 个文件、
  +10166/−2621），以及 `8f61b29`「修复旧版 Agent 预设数据库升级」。
  上游在发布后把 `v0.1.2` 这个 tag **强制移动**到了后者，等于重新发布过一次。
  作者前端运行时、内容管理能力，新增 jquery / vue / pixi.js / showdown / toastr 等依赖。
  rebase 11 个自有提交**零冲突**。
- **适配上游的两处机制变化**：`patches/` 目录上游自己也开始使用（我们的补丁脚本与门禁
  改为只认 `NNNN-*.patch` 命名）；Dockerfile 的依赖安装层需要提前拷入 `patches/`。

### 一直具备的能力

- **Docker 多用户 Web 服务**：单实例多租户，每用户一个独立的 cordis 容器，
  空闲回收；会话列表、角色、模型配置各自隔离。
- **上游可一条线更新**：改动全部落在新增文件里，另配 2 个构建期补丁
  （POSIX 媒体路径分隔符、卡片跨源帧），由门禁脚本强制。
- **手机竖屏适配**：图标栏改为底部横排、正文宽度回收（390px 屏上正文从
  205px 提到 316px）、聊天壁纸铺满、模型选择弹窗改为上下两段、
  生成统计条换行可读、点抽屉外空白处收起侧栏。
- **自有页面与应用同一套外观**：登录 / 账号管理 / 用户管理三页复用应用的设计令牌，
  跟随亮暗主题。
- **站点图标**：上游 `index.html` 没有 favicon，这里补上了。
- **验收体系**：`pnpm webui:verify` 共 17 组、147 项断言，含浏览器端真实渲染检查
  （用 CDP 精确设定手机视口，绕开无头 Chromium 的 500px 宽度下限）。

## 许可证

AGPL-3.0-or-later，与上游一致。

本分支修改了上游代码并以网络服务形式提供，因此按 AGPL §13，
**使用本服务的人有权获得对应的完整源码**——即本仓库这个 tag：

<https://github.com/darling2077/ElecKoi-web>

部署自己的实例时，请把 `ELECKOI_SOURCE_URL` 指向**你自己那份源码**的地址，
服务界面会把它展示给使用者。
